# Design Principles

*Created 2026-07-30*

This document describes the design principles that guide every feature, screen, and interaction within **My Assistant**.

Whenever a new feature is proposed, it should be evaluated against these principles. If a feature violates several of these principles, it should be redesigned before implementation.

---

# 1. Put the User First

The application exists to help the user accomplish tasks more easily.

Every design decision should improve the user's experience rather than adding unnecessary complexity.

---

# 2. Reduce Mental Clutter

The assistant should simplify life—not create more work.

Avoid unnecessary notifications, interruptions, pop-ups, and decisions whenever possible.

---

# 3. Quiet by Default

The assistant should wait patiently until needed.

Notifications should be meaningful, user-configurable, and used sparingly.

The assistant should be helpful—not nagging.

---

# 4. Minimize Typing

Typing is one of the slowest forms of data entry.

Whenever practical:

- Use pick lists.
- Use check boxes.
- Use sliders.
- Use date pickers.
- Use voice input.
- Use photo recognition.
- Automatically calculate values.
- Remember previous entries.

The application should minimize keyboard use whenever possible.

---

# 5. Minimize Taps

Every unnecessary tap creates friction.

Whenever practical:

- Prefer one tap over three.
- Eliminate unnecessary confirmation dialogs.
- Keep common actions close together.
- Make frequently used functions immediately accessible.

---

# 6. Make Touch Targets Comfortable

Buttons should be easy to see and easy to touch.

Avoid tiny controls that are difficult to use on phones.

Touch-friendly design should always take priority over squeezing more information onto the screen.

---

# 7. Use the Appropriate Keyboard

Whenever possible:

- Numeric fields should display the numeric keypad.
- Email fields should display the email keyboard.
- Telephone fields should display the phone keypad.
- Date fields should use date pickers.

Reduce typing errors by presenting the correct input method.

---

# 8. Personalize the Experience

The software remains generic.

The user's experience is personal.

Examples include:

- User name
- Assistant name
- Theme
- Units of measurement
- Reminder preferences
- Home screen layout
- Favorite links

Nothing personal should be hard-coded.

---

# 9. Earn the User's Trust

The assistant should become something the user enjoys opening every day.

It should never surprise the user with unnecessary interruptions or unwanted behavior.

Trust is earned through consistency, reliability, and respect.

---

# 10. Keep Information Together

Whenever practical, information should be connected rather than isolated.

Examples:

- Weather with exercise
- Nutrition with weight
- Medications with symptoms
- Appointments with reminders

The assistant should remember relationships between information.

---

# 11. Build for Growth

The application should evolve naturally over many years.

Features should be modular so new capabilities can be added without redesigning the entire application.

---

# 12. Quality Over Quantity

A few polished features are better than dozens of unfinished ones.

Every feature should feel complete before moving to the next.

---

# 13. Build Like a Craftsman

Every screen should reflect thoughtful design and careful attention to detail.

Like a well-crafted piece of furniture, the application should improve through continuous refinement rather than constant replacement.

The goal is not simply to finish the project.

The goal is to build something that will be enjoyed and appreciated for many years.

---

# Design Test

Before implementing any feature, ask:

• Does this reduce work for the user?

• Is it simple?

• Is it intuitive?

• Does it avoid unnecessary interruptions?

• Does it minimize typing?

• Does it minimize taps?

• Does it respect the user's preferences?

• Would I enjoy using this every day?

If the answer to several of these questions is "No," reconsider the design before writing code.
"Technology should adapt to people—not require people to adapt to technology."
